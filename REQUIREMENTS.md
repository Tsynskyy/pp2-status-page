# Требования

## Проблема и цель

Проблема: у команды несколько сервисов и сложно следить за их доступностью

Цель: страница со статусами и инцидентами

Пользователи: оператор и гость

## Функциональные требования

1. Гость может читать без входа
2. Менять данные может только оператор с токеном доступа
3. Оператор может добавляет сервис с названием и URL
4. Оператор может менять название и URL сервиса
5. Оператор может удалять сервис вместе с историей
6. Сервер сам проверяет все сервисы через заданный интервал и сохраняет код ответа, время ответа и ошибку
7. Сервис получает статус по последней проверке: работает (2xx или 3xx), не работает, нет данных
8. При падении и восстановлении сервер сам открывает и закрывает инциденты
9. Оператор может вручную открыть и закрыть инцидент
10. Пользователь видит историю последних 100 проверок сервиса и доступность в процентах

## Нефункциональные требования

1. Описание API в формате OpenAPI открывается по адресу `/docs`
2. `/status` отвечает быстрее 200 мс при 50 сервисах
3. Ответы API не ждут проверок
4. Один зависший сервис не задерживает проверку остальных больше чем на 5 секунд
5. Сервер отвечает 4xx с JSON на неверные входные данные и не пишет их в БД
6. Токен оператора и пароль БД задаются только через переменные окружения
7. После перезапуска сервера все данные остаются
8. Когда БД доступна `/health` отвечает 200 и 503 если нет
9. Сервер и БД запускаются командой `docker compose up`
10. Сервер - модуль на Python 3.12 и FastAPI, БД PostgreSQL
